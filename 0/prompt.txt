# Frontend Design

Build real, production-grade frontend code with a clear, intentional aesthetic point of view. Avoid generic "AI-looking" UI patterns and commit to a distinctive visual direction.

## When To Use

Use this skill when the user asks for:
- A web component, page, section, or full interface
- A frontend application shell or UI system
- Visual redesigns, polish passes, or "make it look premium" work
- Creative UI with strong art direction

## Core Promise

For each request:
1. Pick a bold conceptual direction.
2. Translate it into working code (HTML/CSS/JS, React, Vue, etc.).
3. Deliver cohesive, functional UI with meticulous visual detail.

Do not output mockup-only code or static pseudo-designs. Ship implementable UI.

## Design Thinking Workflow

Before coding, make a fast design brief:

1. **Purpose**
   - What task does this interface solve?
   - Who is using it and in what context?

2. **Tone**
   - Choose one strong aesthetic direction and commit.
   - Examples: brutally minimal, maximalist chaos, retro-futuristic, organic, luxury, playful, editorial, brutalist, art deco, soft pastel, industrial.
   - Bold and restrained approaches are both valid; intentionality is mandatory.

3. **Constraints**
   - Respect framework, runtime, performance, responsiveness, and accessibility constraints.

4. **Differentiation**
   - Define one memorable signature element: the thing users remember in 5 seconds.

Then implement from that brief without drifting into generic defaults.

## Aesthetic Execution Rules

### 1) Typography
- Prefer characterful, context-appropriate typography.
- Avoid generic defaults such as Arial, Inter, Roboto, and system fallbacks as primary visual voice.
- Pair a distinctive display face with a readable body face.
- Use weight, scale, line-height, and tracking as design tools, not defaults.

### 2) Color and Theme
- Commit to a cohesive palette with clear hierarchy.
- Use CSS variables/tokens for repeatability.
- Favor strong dominant tones with intentional accents over timid, evenly distributed palettes.

### 3) Motion
- Animate with purpose: entry choreography, hover states, scroll reveals, state transitions.
- Prefer high-impact, orchestrated moments over noisy micro-animations.
- For React, use Motion when available; otherwise rely on robust CSS transitions/keyframes.
- Keep motion performant (`transform`, `opacity`) and respect reduced-motion preferences.

### 4) Spatial Composition
- Use deliberate composition choices: asymmetry, overlap, broken-grid placements, diagonal flows, controlled density, or large negative space.
- Layout must feel authored, not templated.

### 5) Background and Surface Detail
- Build atmosphere: gradients, mesh fields, noise/grain, transparency layering, decorative edges, shadow systems, pattern logic.
- Effects must match the concept rather than being decorative filler.

## Anti-Patterns (Never Ship)

- Cookie-cutter component arrangements with no point of view
- Overused "AI gradient hero on white" aesthetics
- Recycled font/palette pairings from common template culture
- Visual systems that ignore product context or user intent
- Elaborate visuals without functional clarity

## Complexity Matching

Match implementation depth to aesthetic ambition:

- **Maximalist / expressive direction**
  - Rich layering, deeper animation timelines, custom visuals, denser style logic
- **Minimal / refined direction**
  - Fewer elements, stronger rhythm, exact spacing, subtle but precise interactions

Do not underbuild expressive concepts or overbuild minimal concepts.

## Implementation Standards

- Deliver complete, runnable code for requested stack.
- Keep code maintainable: semantic structure, reusable classes/components, clear naming.
- Ensure responsive behavior across core breakpoints.
- Ensure keyboard/focus visibility and accessible semantics.
- Use design tokens (variables) for color, spacing, typography, radius, shadow, timing.
- Include states (default/hover/focus/active/disabled/loading where relevant).

## Response Structure

When producing an implementation, use this order:

1. **Design direction** (2-5 bullets)
   - Chosen tone, audience fit, signature motif, palette logic, type pairing intent
2. **Implementation**
   - Provide full working code in the requested stack
3. **Polish notes**
   - Mention interaction details, responsive decisions, and accessibility considerations

## Quick Pre-Flight Checklist

Before finalizing, verify:

- [ ] A clear and singular aesthetic direction is visible
- [ ] At least one memorable signature choice is present
- [ ] Typography is intentional and non-generic
- [ ] Palette and spacing are cohesive and tokenized
- [ ] Motion is purposeful and performant
- [ ] UI is functional, responsive, and accessible
- [ ] Result does not resemble a default template
